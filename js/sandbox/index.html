      The language

      applecontains, case-insensitive — the default
      apple*pie* — any run of characters, including none
      `applebacktick at the start — anchor to the beginning
      apple`backtick at the end — anchor to the end
      `apple`both — an exact match
      apple|pear| — either alternative
      \c\`apple`options prefix — c makes it case-sensitive
      \*backslash escapes a reserved character
      \\a literal backslash — on its own, it finds labels containing one
      \c\applethe option prefix needs at least one letter, so \\ above stays an escape

      Character sets

      v[12]-draft[…] is a set — exactly one character from it, here 1 or 2
      x[0-9]ysets take ranges: 0-9, a-z, A-Za-z, 0-9A-F
      [0-9].pdfa set may open a pattern — nothing has to precede it
      `[A-Z]foobeside an anchor, with nothing special required
      bar[456]`a set, then the end anchor
      a\[b\]ca literal bracket is escaped

      A set is always case-sensitive — a literal is not. `[A-Z]ocker matches Dockerfile and DOCKERFILE but not dockerfile: the set refuses the lowercase d while the literal folds. Ask for both cases and you get both: [A-Za-z]. \c\ governs literals only.

      A backtick is an anchor and nothing else — first character, last character, or a mistake. Until 2026-09-22 it delimited sets too, and that one overload caused every confusion this language ever had; brackets ended it, along with an entire section of the specification.

      Groups

      `||a|b||`||…|| groups alternatives — here exactly a or b
      *.||md|txt||the shared part is written once, not once per alternative
      `||src|test||/an anchor belongs to the alternative, so it reaches every branch
      a\|\|ba literal || is escaped, exactly as a literal | always was

      A group does not nest, and three or more | in a row is an error rather than a guess. That one rule is also why two groups cannot touch — ||a|b||||c|d|| is a run of four, so put a character between them — and why an empty group cannot be written at all. An unclosed || is refused too, so a half-typed pattern hides nothing.

      Options

      \c\applecase-sensitive literals
      \-\testnot — hide every label the pattern finds
      \b\appwhole word — app, app-1, my app, app_data; not apple
      \c-b\Appthey compose, in any order

      A boundary is the edge of the label or a neighbouring character that is not a letter or a number — so _ separates words, which regex's own \b gets wrong for filenames. And \-\ is an exclusion filter: \-\a|b is NOT (a OR b). Apple but not test needs two filters, by design.

      `a|b` is refused. Anchors bind to the alternative they are written in, so it used to mean starts with a OR ends with b while reading like exactly a or b. Write `||a|b||` for the reading you expect.

      Six characters are reserved and nothing else is special: * | ` \ [ ]. An unparseable pattern hides nothing — it matches everything and says why, rather than silently emptying the list.
